# Домашнее задание к занятию «Репликация и масштабирование. Часть 2». Соколов И.В. 

### Задание 1

Опишите основные преимущества использования масштабирования методами:

- активный master-сервер и пассивный репликационный slave-сервер; 
- master-сервер и несколько slave-серверов;


*Дайте ответ в свободной форме.*


### Решение 1

 1. Активный master-сервер и пассивный репликационный slave-сервер

 Данная конфигурация направлена на обеспечение отказоустойчивости (High Availability), а не на распределение нагрузки.
 Преимущества:

- Высокая доступность и быстрое восстановление (Failover). 

- Простота технического обслуживания. 

2. Master-сервер и несколько slave-серверов

Данная конфигурация ориентирована на масштабирование производительности.

- Возможность горизонтального масштабирования на чтение.

- Повышение общей производительности Master-сервера за счет высвобождения от операций на чтение.

### Задание 2


Разработайте план для выполнения горизонтального и вертикального шаринга базы данных. База данных состоит из трёх таблиц: 

- пользователи, 
- книги, 
- магазины (столбцы произвольно). 

Опишите принципы построения системы и их разграничение или разбивку между базами данных.

*Пришлите блоксхему, где и что будет располагаться. Опишите, в каких режимах будут работать сервера.* 

### Решение 2

1. Cначала разделим таблицы по разным серверам функционально (вертикальный шаринг), а затем распределим строки самой нагруженной таблицы (пользователи) по нескольким узлам (горизонтальный шаринг).

2. Пример структуры данных:

- Users (Пользователи): id, email, password, first_name, last_name

- Books (Книги): id, title, author, price, description.

- Shops (Магазины): id, name, address, phone.


3. Вертикальное шардирование (разделение по функциональности)

Мы разделяем систему на три логических дата-узла на основе бизнес-логики и характера нагрузки:

- Узел Пользователей (User Cluster): Самая высоконагруженная часть (частая авторизация, обновление профилей). Требует горизонтального масштабирования.

- Узел Книг (Catalog/Books DB): Средняя нагрузка на чтение, редкая запись. 

- Узел Магазинов (Shops DB): Низкая нагрузка, статические данные.

4. Горизонтальное шардирование (разделение таблицы Users)

Таблица Users распределяется между двумя серверами (Шард 1 и Шард 2) на по ключу id: нечетные — на Shard 1, четные ID идут на Shard 2.

5. Режимы работы серверов (Архитектура)

Для обеспечения отказоустойчивости и высокой доступности каждый элемент системы дублируется:

- Маршрутизатор (Sharding Proxy / API Gateway): Принимает запросы от бэкенда. Он знает карту данных (Metadata) и перенаправляет запросы на нужный шард или узел.

-  Узел Users (Шардированный):

	• Shard 1 Master: Запись и чтение (Нечетные ID).

	• Shard 1 Replica: Репликация для Shard 1.

	• Shard 2 Master: Запись и чтение (Четные ID).

	• Shard 2 Replica: Репликация для Shard 2.

- Узел Books: 

	• Master: Принимает изменения каталога книг.

	• Replica: Обслуживает массовое чтение каталога клиентами.

- Узел Shops:

	• Master: Принимает изменения списка магазинов.

	• Replica: Обслуживает массовое чтение списка магазинов клиентами.
